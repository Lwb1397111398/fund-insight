# 附：S4a-v7.2 收尾修订（评审 87 分后回填；本表覆盖 v7/v7.1 的对应条目）

评审员重跑了 145 个板块名 × 27879 条名册，又抓出一个**我自己在 v6 就写进去的 bug**，
它同时解释了为什么上一轮"医疗"选成了 159877 而不是龙头 512170。

## 一、必须改的 7 条（逐条给准话）

1. **沪市 ETF 被静默丢掉（真 bug）**：`suggest_exchange_etf` 里写的是
   `code[:2] in ('15','5')` —— `'512170'[:2] == '51'`，**永远不匹配**，
   986 只沪市 ETF（51/52/56/58 段）全部进不了候选池，排序键"51/56 段优先"也因此是死代码。
   → 改成 `code[:2] in ('15','16','51','52','56','58')`（与 `is_exchange_listed` 的
   `^(15\d{4}|5\d{5})$` 对齐），并加 `test_sh_etf_not_dropped`（512170/512070/561510 必须在候选里）。
   连带后果：**"这 6 条要等 LLM"是错的** —— 补上沪市段后，保险 → **512070 证券保险ETF** 可确定性修复；
   可确定性修复的板块从 29 个涨到 39 个（本轮实测）。
2. **核心词规则要能被测试**：`sector_core()` 明确按
   `norm = normalize_sector_name(sector)` → 若含数字或拉丁字母则**取 norm 整串**（不再剥尾）→
   否则剥泛指尾 `板块|概念|主题|指数|行情|方向` → 再查 stop-list。
   实测 145 个板块名：**130 个有核心词、15 个被拒**（市场/大盘/宽基/宽基指数/全球/综合/设备/资源/
   资源股/业绩/应用/老登/韩股→韩/台股→台/A股→A）。v7 里 `SpaceX概念→''`、`全A指数→''` 两句
   与本规则矛盾（按本规则得到 `SpaceX`、`全A`），测试期望以此为准。
3. **删掉"应用→021252"这一行**：`应用` 在 stop-list 里（核心词被拒），且 021252 是
   "华安中证信息技术应用创新产业指数发起式A"——**场外、还是信创**，违反自家规则。id 60 留给 LLM。
4. **重新仲裁不能用 `official_name == 名册[code]` 断言**：实测 145 行里 **13 行今天就不相等**
   （含 `ok` 行 109/131/145），而且名册里没有 000938/002154/002261 这类码（值为 None）。
   更要紧的是**自我背书**：realign 用名册写 `fund_name`，再拿名册仲裁 → Jaccard 恒 1.0 → 恒 `ok`。
   → 断言改成 `official_name == get_fund_domain_name(code)['name']`，并且**非循环校验**必须包含：
   ①候选的"指数段"含板块核心词；②`verify_fund_fetchable` 严格通过 + 净值距今 ≤30 天。
   换标的后必须一并复位的字段（v7.1 只提了 `confidence`，这里给全）：
   `confidence/match_kind/match_source/llm_reason/keywords/evidence.identity.suggested_code/
   evidence.etf_upgrade/verify_message/verified_at`。
5. **换过标的的行不能保留 `reviewed=True`**：`_mapping_eligible` 对 `owner_locked/reviewed_by='owner'`
   是**无条件放行**的，等于让 agent 替老板批了审查；而 `update_mapping`/`mark_reviewed_by_id` 早已把
   "换代码"当作结论作废。→ realign 一律 `reviewed=False, owner_locked=False, reviewed_by=None`，
   进老板的一键审查清单。
6. **回滚要真的能回滚**：`restore()` 只对 `verified_at` 做了 `fromisoformat`，补进 `updated_at`
   会把字符串塞进 DateTime 列（SQLite 直接 TypeError）；本轮 `ensure_fund_info_exists` 新建的
   `fund_info` 行也不在任何清单里（会漏在基金列表里并被同步任务拉历史）；还原后没刷缓存。
   → manifest 记录**新建档案的代码列表**，restore 里删掉这些行；所有日期列统一走类型还原；
   restore 结束调用 `refresh_cache()` + `invalidate_denied_cache()`。
7. **`normalize_sector_name` 会把 债券 改写成 券商**（id 147 老板行就是靠 owner_locked 才没出事）：
   核心词/候选都按"券商ETF"算。→ realign 全程**跳过 owner 锁定行**，并把这条别名风险写进报告；
   别名表（`SectorAlias` 现为 0 行）的补齐是零 LLM 的确定性活儿，列入本轮副产品。

## 二、度量改法（"预测改动 0 条"是必然成立，不算成绩）

- 报**"若老板批准，预计改标 N 条 / 受影响博主 M 个"**（实测每板块预测数：储能 8、中药 10、养殖 1、
  保险 2、AI 5、信创 0、5G 0）。
- 报**"补上沪市段后新增可确定性修复板块数 29 → 39"**。
- `relevance_low` 集合以计算结果为准：**{121 5G, 122 AI, 134 保险, 135 信创, 136 储能, 140 养殖} = 6 条**
  （v7.1 写的 8 条含 30/69/139/35 是错的：35 因"业绩"在 stop-list 里根本进不来）。
- 大小写归一：`Ai应用`/`AI`、`5G`/`5g` 必须等价（核心词与指数段比较前统一 upper）。
- "更长的已知板块名"这条排除规则必须可判定：改为**最长认领**——把所有板块核心词按长度降序排，
  每只候选 ETF 只被"能命中它的最长核心词"认领；一个核心词若被更长核心词抢先命中则放弃。
  （旧写法实测既把 159687 从"亚太"里排掉、也把 4 只从"中概"里排掉，方向完全错。）
