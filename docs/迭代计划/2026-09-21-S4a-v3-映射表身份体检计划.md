## 一、本轮真正查出来的根因（比"股票污染"更底层）

现场复测（`verify_fund_fetchable(probe_stock=True)`，5 个码，全部 `ok=True`）：

| 映射表存的 | 存的名字 | 基金域同一码的**真实**品种 | 结论 |
| --- | --- | --- | --- |
| 000725 | 京东方Ａ | 大成添利宝货币B（货基，20 条历史） | 旧版"验证抓取"=通过 |
| 000970 | 中科三环 | 东方红睿元混合 | 同上 |
| 000530 | 冰山冷热 | 招商丰盛稳定增长混合A | 同上 |
| 002273 | 水晶光电 | 宏利创益混合B | 同上 |
| 510300 | 沪深300ETF华泰柏瑞 | 沪深300ETF华泰柏瑞 | 正常 |

`src/fund/fund_api.py:387` 的 `if ok: return 'fund'` 让"能抓到净值"直接等于"是基金"。但 6 位代码在 A 股与场外基金之间**码段重叠**（000xxx/001-003xxx/300xxx 既是深市股票也是基金代码），所以：

> **能抓到净值 ≠ 抓到的就是我们要的那只基金。**

这才是老板抱怨的最底层机制：板块→股票代码→同码的货币基金→用货基净值去验证"京东方看涨"→永远得出无意义的结论。145 行全表复测：`kind='stock'` **0 条**、`unknown` 6 条（4 条本就 reviewed=0）——即现有 agent 的"必须验证是基金不是股票"这一关，**对这类行全部形同虚设**。

判定方法（确定性、零 LLM）：**名字一致性仲裁**。同一码同时取基金域名 F 与股票域名 S，与映射表存的名称分别做 Dice 相似度：
- `sim(stored, S) >= 0.5 且 sim(stored, S) > sim(stored, F)` → `stock`（京东方Ａ vs 京东方A ≈ 1.0，vs 大成添利宝货币B ≈ 0.07）
- `sim(stored, F) >= 0.35` → `fund_confirmed`
- 其余 → `identity_mismatch`（基金域有码但不是这只）
- 两边都无数据 → `unknown`
- 码段 15xxxx/5xxxxx（场内基金专用段，A 股无此段）→ 不做仲裁，只走"是否场内 ETF"纯度判定。
