## 一、匹配规则重定义（这是本轮的核心，单独钉死）

`sector_core(sector)`：
1. `norm = normalize_sector_name(sector)`；
2. 剥泛指尾（`板块/概念/主题/指数/方向/板块行情/行情/股`）；**含数字的名字不剥**（中证500 剥成"中证"就是灾难）；
3. 若 `norm` 含数字或拉丁字母（`5G`、`全A`、`SpaceX`、`CPO`）→ 核心词取**整串**，不做中文抽取（避免 `cjk_core('全A指数')='全指数'`）；
4. 结果在泛指 stop-list（`市场/大盘/资源/宽基/指数/权重/龙头/板块/主线/全球/精选/概念/应用/综合/设备/中报/业绩/老登`）内或长度 <2 → **无核心词，不 realign**。

`etf_candidates(core)`：名册里 `15/5` 段 + 官方名含 `ETF` + **把官方名去掉结尾公司名与 `ETF` 字样得到"指数段"**，要求 `core` 出现在该指数段里（储能电池 ⊃ 储能 ✓；港股互联网 vs A股互联网：核心词是"互联网"时两者都命中，但 124 行核心词按第 3 条是"A股互联网"整串，不命中 ✓）。
再加**排他条件**：候选名若含**更长的其它已知板块名**（145 个 `sector_name` ∪ `SECTOR_ALIASES`），该候选作废。
`test_core_matcher_golden`：对全部 145 个板块名跑一遍，产出 `docs/迭代计划/run-2026-09-20/core-matcher-golden.json` 当基线；用例含
`储能→159305`、`信创→159537`、`养殖→159865`、`A股互联网/综合/设备/中证1000/中药 → 按规则给出的确定结果`。

排序键（依次）：①站点新鲜度（`nav_date` 最近，且距今 ≤30 天，停更即拒）；②本地净值条数；③`51/56` 段优先；④代码升序。

## 二、realign 的准入与落笔

| 行的当前状态 | 是否允许 realign | 落笔后 |
| --- | --- | --- |
| `verdict=ok` 且 `relevance_low` 且 `reviewed=True` | 允许 | 换标的 + **重新仲裁身份**（用名册，0 额外请求）+ 重算 `relevance_low` + 重算 `is_fetchable`；`reviewed` 保持 True（标的换了但方向没变，且有完整证据） |
| `verdict=ok` 且 `relevance_low` 且 `reviewed=False`（本轮 135/136/140 就是这种） | 允许 | 同上，但 `reviewed` 保持 False → 进"待老板一键审查"清单，**不自动 reviewed** |
| `verdict ∈ {code_is_other_fund, wrong_code}` 且能解析出对口号（中药→159647 中药ETF鹏华、应用→021252） | 允许（这就是把坏行修好） | 换标的 + 重新仲裁 + `is_fetchable` 按新结论写、`reviewed=False` |
| `verdict=not_a_fund`（9 只股票名） | **禁止**（名字本身是股票，不存在对口基金） | 保持降级 |
| 代码在**代理拒绝集**（512000/159206）内 | 禁止 | 不动 |
