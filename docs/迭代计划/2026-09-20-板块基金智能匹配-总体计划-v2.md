## 四、S2 agent 核心

### S2a 新模块 `src/services/sector_fund_agent.py`

```python
@dataclass
class FundCandidate:
    code: str; name: str; source: str          # t0_reviewed_db|t0_static|llm|search|user
    official_name: str = ""; fund_type: str = ""
    reason: str = ""; name_sim: float = 0.0; t3_score: float = 0.0
    verify: dict | None = None                 # S2b 返回体
    rejected: str = ""                          # 淘汰原因（可观测）

@dataclass
class SectorDecision:
    sector: str; chosen: FundCandidate | None
    alternatives: list[FundCandidate]
    status: str            # matched | needs_review | conflict | no_fund
    confidence: float; rounds: int
    evidence: list[dict]   # 每轮 {round, action, input_digest, output, verdict}
    aliases: list[str]; keywords: list[str]
```

`resolve_sector_fund(sector, hint=None, max_rounds=3, allow_llm=True, budget_ms=12000, db=None) -> SectorDecision`

流程（每步都写 evidence，失败不静默）：
1. **T0 确定性候选**（零网络）：`sector` 经 `sector_alias` 归一 → 只取**精确** `sector_fund_mapping` 与 `SECTOR_FUND_MAP`/`DEFAULT_FUND_MAP` 的精确键；`len(key) < 3` 的键**禁止**子串命中（R1 门槛）。
2. **T1 LLM 提案**：要求返回 `{candidates:[{code,name,company,reason}×3-5], keywords:[...], aliases:[...]}`；prompt 明确"必须是可在天天基金查到的**公募基金**（ETF/LOF/场外指数），不得是股票/债券型/货币型（除非板块语义就是债市）"。
3. **T2 抓站验证**：逐候选调 `classify_and_verify_fund`（S2b）；淘汰条件：非基金 / 抓不到 / `name_sim < 0.35`（代码真实但**是另一只基金**的幻觉，v1 未覆盖）。
4. **T3 语义相关判定**：输入只用**已存在数据来源**的字段——板块名、板块别名、官方基金名、`fund_type`（来自 `search_fund` 的 `FUNDTYPE`，见 S2b）、该板块在库内预测条数；输出 `{suitable, score 0-100, reason}`；`score >= 70` 才通过。（v1 里的"跟踪指数"没有取数来源，已删除，见 MUST-FIX#6。）
5. **T4 关键词搜索回环**：T1/T2/T3 无通过项 → 用 `keywords` 逐个调 `fund_api.search_fund(kw)`（`fund_api.py:407`，天天基金搜索接口，返回天然只含基金）→ 去重后 top-8 连同官方名回灌 LLM 复判 → 命中者回到 T2 完整验证；每轮计入 `rounds`，最多 `max_rounds`。
6. **T5 收口**：`status='no_fund'` 或 `needs_review`，**绝不回落随机基金**；已 `reviewed=true` 的行 T3 不通过 → `status='conflict'`，**只告警不改库**、进 §六"人工裁决清单"（避免把老板手工确认过的行自动改掉）。

**置信度与阈值（不再拍脑袋）**
```
confidence = 0.45*min(1, name_sim/0.7) + 0.35*(t3_score/100) + 0.20*source_prior
source_prior: t0_reviewed_db=1.0, search=0.8, llm=0.7, t0_static=0.6
自动 reviewed 需 confidence>=0.85；0.70<=c<0.85 -> needs_review；c<0.70 -> 不写库
```
两个阈值（T3 的 70、自动审查的 0.85）用**金标集标定**：`docs/迭代计划/gold-standard-40.md` 由我逐条查天天基金人工写 40 条（板块→应得基金 + 理由 + 明确反例，含 `半导体`、`存储`、`债券`、`日股`、`SpaceX`、`CPO`、`豆粕` 等），`scripts/calibrate_sector_agent.py` 跑 confusion matrix；门禁 = 金标集上 **precision ≥ 0.90 且"金标判错配却被自动 reviewed"= 0 条**。

**名称归一化（写死算法，可复核）**：剥离公司前缀（华夏/易方达/南方/国泰/华宝/招商/广发/嘉实/富国/天弘/银华/博时/鹏华/汇添富/华安/建信/工银/兴业/永赢/摩根…取自已导入的 162 只基金名 + 常见清单）、剥离 `ETF|联接|LOF|发起式|指数|基金|份额|A类|C类|A|C` 后缀、去空白标点；再做二字滑窗 **Dice** 相似度 `2|∩|/(|b1|+|b2|)`；`≥0.5` 或互为子串视为名称一致。
