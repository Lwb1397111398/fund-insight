### S2 板块→基金 agent 解析器（核心，预计 2 天）

**新增 `src/services/sector_fund_agent.py`**

```python
@dataclass
class FundCandidate:
    code: str; name: str; source: str        # reviewed_db|static|llm|search|user
    fund_type: str = ""; official_name: str = ""
    reason: str = ""; score: float = 0.0
    verify: dict | None = None                # S2b 的验证结果

@dataclass
class SectorDecision:
    sector: str
    chosen: FundCandidate | None
    alternatives: list[FundCandidate]
    status: str                # matched | needs_review | no_fund
    confidence: float          # 0..1
    rounds: int                # agent 实际轮数
    evidence: list[dict]       # 每轮：动作/输入/输出/判定，前端可展开查看
    aliases: list[str]         # 建议写入 sector_alias 的别名
```

`SectorFundAgent.resolve(sector, hint=None, max_rounds=3, allow_network=True, allow_llm=True) -> SectorDecision`，流程：

1. **T0 确定性候选**（零网络，快路径）：`sector` 经 `SectorAlias` 归一后，**只做精确匹配**取已审查 `sector_fund_mapping` + `SECTOR_FUND_MAP`。≤2 个候选时同样送 T3 语义判定，不直接采信（这正是 R1 的病灶）。
2. **T1 LLM 提案**：一次调用要回 `{candidates:[{code,name,reason,scale,index_tracking}], keywords:[...], aliases:[...]}`，要求 3–5 个**不同基金公司跟踪同一指数**的候选，显式禁止股票/债券/货币/理财（除非板块本身是债市）。
3. **T2 抓站验证**（复用并加固 `fund_api`，见 S2b）：逐个候选验证 `is_fund && fetchable && name_ok`；`name_ok` = LLM 声称名 vs 官方名的字符重合度 ≥0.5，防止"代码存在但是另一只基金"的幻觉。
4. **T3 语义相关性判定**：把 `板块 + 官方基金名 + fund_type + 跟踪指数`交给 LLM 判定 `{suitable, score 0-100, reason}`；只有 `score≥70` 才算通过。**这是"八竿子打不着"的根治点**。
5. **T4 关键词搜索回环**（老板设想的 agent 路径）：T1/T2/T3 全失败 → 用 `keywords` 调 `fund_api.search_fund(kw)`（`fund_api.py:407`，天天基金搜索接口，返回体天然只含基金）→ top-N 连同官方名回灌 LLM 复判 → 命中则回到 T2 验证。最多 `max_rounds` 轮，每轮都记进 `evidence`。
6. **T5 收口**：无任何通过项 → `status='needs_review'`（或 `no_fund`），**绝不**回落成随机基金；有通过项但 `confidence<0.7` → 也标 `needs_review`，前端红点提示。

降级顺序（`allow_llm=False` 或 LLM 熔断打开 / 无网络时）：T0 精确 → 现有 `SECTOR_FUND_MAP` → 现有 `search_fund[0]`（仅记 `confidence=0.2` + `needs_review`）。**行为不比今天差**，且不会因为 LLM 挂了而卡住帖子分析主链路。

**改动既有代码（收敛 R4）**
