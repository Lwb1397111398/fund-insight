# 投资建议模块总览

## 模块职责（一句话）

把库里攒下的博主观点与预测，加上系统按宽基指数净值算出的"大盘状态"，交给 LLM 分三段分析，
产出一份**说人话、给明确动作**的投资建议（买/加/持/减/全部卖出/回避/只看不动手），校验合格才落库、上页面。

## 运作流程（按数据真实流动顺序）

1. **入口**：前端「投资建议」页点「🚀 生成投资建议」→ `POST /api/advice`（`src/api/routes/advice.py`，
   行号以 `grep -n "@router.post" src/api/routes/advice.py` 现读）；
   进页面也会 `GET /api/advice` 拉最新一条（2026-10-12 补的接线，以前刷新就回空态）。

2. **选证据**：`AdviceService.get_data_for_advice()`（`src/services/advice_service.py:160`）内部走
   `AdviceEvidenceBuilder.build()`（`src/services/advice_evidence.py`），挑四类东西：
   - 博主：准确率≥50% 且样本≥3，按准确率取前 15（准确率=预测验证模块算的加权命中率）；
   - 预测：只取 `filter_actionable_current`——未验证、未到期、目标日在未来（近期7天全收、中期30天限20条），
     同一博主限 3 条防一人多票；
   - 观点：近 7 天，按 `credibility_score×weight` 排序、同一作者限 3 条、全局 50 条；
   - **市场闸（2026-10-12 新增）**：`src/analyzer/market_state.py` 的 `compute_market_state()`
     纯本地读 `fund_history` 里宽基 ETF 净值（主 510300 沪深300ETF华泰柏瑞，缺数据退 510050/510100），
     算近 5 日、近 20 日涨跌与自窗口高点回撤，按常量阈值分四档：
     近20日≤-6%且5日续跌=极弱（建议空仓）、≤-3%或回撤≥8%=弱势（减仓为主不新开仓）、
     ≥+3%且5日在涨=强势、其余=震荡；净值点<6 ⇒ `unknown`，闸自动失效不硬拦。

3. **证据不足先拒绝**：`validate_evidence_for_advice()`（`src/services/advice_validation.py`）——
   没有任何可行动预测就回 `no_actionable_predictions`，一次 LLM 都不调。

4. **缓存判断**：`cache_key = evidence_hash|ADVICE_PROMPT_VERSION|模型版本`。
   `evidence_hash` 把入选证据和**市场闸结果**（档位+净值日+涨跌数）一起 SHA256——
   所以每天净值一更新，旧建议缓存自动失效、必须重算。
   版本常量 2026-10-12 升到 `advice.three_stage.v2`。

5. **三段式 LLM 分析**（`src/analyzer/llm_analyzer.py`）：
   - 阶段1 `analyze_viewpoints_stage1`：近 7 天观点压成短字段喂 LLM，出市场情绪/热门/风险板块；
   - 阶段2 `analyze_predictions_stage2`：≤30 条预测（带博主等级、权重、剩余天数）+ 阶段1摘要，
     出板块看涨/看跌/中性计数；**无预测直接标 failed**；
   - 阶段3 `generate_advice_stage3`：阶段1/2结果 + 博主准确率 + **【市场整体状态】事实块**，
     出最终 JSON：`position`（跟随/逆闸+理由）、`sector_actions`（每板块一个动作，七档枚举）、
     以及兼容旧展示的 `advice_content`/`short_term`/`mid_term`/`avoid_sectors`。
     提示词硬性要求：第一句先给仓位结论、**全文禁用"关注"**、卖出理由用"若持有…"条件句式。

6. **落库前双闸**（`src/services/advice_validation.py::validate_advice_output`）：
   - 任一阶段 failed 或缺阶段标记 ⇒ 拒（fail-closed，老规矩）；
   - `sector_actions` 必须非空且动作在七档枚举内，中文动作标签由后端统一挂；
   - `advice_content` 出现"关注"或没有任何动作词 ⇒ 拒；
   - **软闸一致性**：大盘 `weak/very_weak` 时仍出现买入/加仓（或 advice_type=buy）⇒
     必须 `follow_gate=false` 且写明 `override_reason`，缺一条就拒（老板定的"AI 可逆闸但要说理由"）。

7. **附挂标的 + 落库**：路由把校验过的 normalized 交给
   `_attach_sector_fund_targets()`——用 `src/constants/sector_fund_map.py::get_fund_for_sector`
   给每条板块动作找具体基金（如 红利→510880、医药→512010）；**映射答不出就留空，代码不由 LLM 报**（它会编）。
   然后 `AdviceService.create_advice()` 写 `investment_advice` 表（v2 新增 3 列：
   `market_stance`、`position_advice`(JSON)、`sector_actions`(JSON)；老行保持 NULL，读路径容忍）。

8. **前端渲染**（`web/index.html` 建议视图 + `web/common.css`）：
   仓位指挥牌（stance 分色、position_label、数据依据、AI 逆闸理由黄条）→
   板块操作清单（七档彩色徽章 + 置信度 + 大白话理由 + 标的基金）→ 短期/中期块 → 风险提示。
   老建议没有 `sector_actions` 时回退显示旧「建议板块（未标动作）」块。

## 入口文件清单

| 文件 | 角色 |
| --- | --- |
| `src/api/routes/advice.py` | POST/GET 端点、附挂标的、拒绝日志 |
| `src/services/advice_service.py` | 取证据、缓存键、落库、历史 |
| `src/services/advice_evidence.py` | 证据包构建（博主/预测/观点/市场闸/哈希） |
| `src/analyzer/market_state.py` | 大盘状态纯计算（软闸唯一真值） |
| `src/analyzer/llm_analyzer.py` | 三段式 LLM（stage1/2/3 在 :1705/:1764/:1866 附近） |
| `src/services/advice_validation.py` | 证据门 + v2 输出契约/软闸/措辞校验 + 缓存版本 |
| `web/index.html`（建议视图）、`web/common.css` | 仓位牌/操作清单渲染 |

## 对外接口 / 被谁调用

- `POST /api/advice`（`{force}`）、`GET /api/advice`、`GET /api/advice/history`——全部被 `web/index.html` 用；
- 被引用：`mobile/lib` 无调用；数据保留/清理模块会删 `investment_advice` 行（`retention_*`）。

## 上游依赖

- 预测验证与准确率统计模块（博主 accuracy_rate/grade 的唯一来源）；
- 基金数据抓取与验证模块（`fund_history` 宽基净值 ⇒ 市场闸）；
- 帖子录入与 LLM 分析模块（`viewpoints`/`predictions` 内容）；
- `src/constants/sector_fund_map.py`（板块→基金附挂）；
- LLM 渠道（`llm_analyzer`，主/辅渠道自动切换）。

## 关键数据结构

- `investment_advice` 新三列：`market_stance` VARCHAR(20)、`position_advice` JSON、`sector_actions` JSON；
- 市场闸 dict（`compute_market_state` 返回）：`stance/stance_label/position_label/enforce/index_code/index_name/nav_as_of/r5/r20/drawdown/window_days/basis`；
- v2 建议输出：`position{follow_gate,position_label,override_reason}`、
  `sector_actions[{sector,action,action_label,confidence,reason,horizon,fund_code,fund_name}]`；
- 阈值全在 `market_state.py` 顶部常量（`VERY_WEAK_R20=-6.0` 等），调档只改这一处。

## 已知坑与约束

- **2026-10-12 之前生成的建议没有这三列**（全 NULL）：页面靠 `v-if` 回退旧块，不会报错，
  但旧文案仍可能含"关注"——那是历史数据，读路径不跑校验、不改写。
- `dry_run` 是**查询参数**不是请求体字段（`POST /api/predictions/sync-sector-mapping` 那条老教训同样适用于
  本仓所有"预览 vs 执行"接口；本模块没有 dry-run，但 force 走请求体是有效的）。
- 市场闸依赖宽基净值：镜像/生产若 510300 断更 ⇒ 自动退 510050/510100，都缺 ⇒ `unknown` 不拦人。
  净值滞后多少天建议在页面上是看得见的（basis 里带净值截止日期）。
- LLM 撞 TPM 限流（429）时按阶段失败处理、**不落库**（fail-closed 验证过：2026-10-12 镜像实测连拒两次、第三次才成）。
- 生厂商汤/火山 key 欠费时 stage 失败会一直拒——那是凭据问题不是代码问题，先看服务日志的 403 原文。
- 测试里 `conftest.BlockedRealHttp` 拦网络：给本模块写新用例不要真打 LLM，桩在 `_call_llm` 层（见
  `tests/unit/test_advice_executable_contract.py` 的 `_CapAnalyzer`）。
- 生产加列走 `scripts/sync_db_columns.py`（先不带 --apply 的 dry-run → `--apply --confirm SYNC-COLUMNS` → 复核），
  2026-10-12 已在镜像演练通过；生产待老板确认。
