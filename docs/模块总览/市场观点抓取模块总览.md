# 市场观点抓取模块总览

## 模块职责（一句话）

手动触发地把"当天市场观点"从三个来源（新浪博客、东方财富热门股吧、天天基金热门基金吧）抓回来，
逐条过门禁后存进 `viewpoints` 表，供后续批量 AI 分析和"市场观点汇总"使用。

## 运作流程（从哪来 → 怎么处理 → 产出什么 → 影响谁）

1. **入口**：前端观点页「抓取分析/抓取最新观点」按钮（`web/viewpoint-manager.js` 的
   `fetchLatestViewpoints`）→ `POST /api/viewpoints/fetch`（`src/api/routes/viewpoints.py`），
   请求体 `sources`（三选多）与 `limit_per_source`（1~50，前端现传 50）。
2. **建任务**：`ViewpointWorkflowService.create_fetch_task`（`src/services/viewpoint_workflow_service.py`）
   建一条 `batch_analysis_tasks`（task_type=`viewpoint_fetch`），同类型活任务存在则复用（幂等）。
3. **逐源抓取**（`_default_fetchers`，全部真网络 HTTP，无构建依赖）：
   - `sina_blog`：`src/crawler/sina_blog_crawler.py` 抓 `finance.sina.com.cn/roll/feed.d.html?lid=1001`
     列表页（每页约 45 条、按时间倒序），只收当天（北京日）博文，逐条经微博文章 API 补正文；
     额度 = `_cap(limit, 50)`（2026-10-13 起从 20 放开到 50，新浪当天约 45 条基本能收全）。
   - `stock_guba`：`src/crawler/stock_guba_crawler.py` 抓三个指数吧
     （`zssh000001` 上证 / `sz399001` 深证 / `sz399006` 创业板），
     列表页内嵌 `var article_list=` JSON（每页约 80 条）→ **先按当天过滤**（2026-10-13 新增，
     热门旧帖不再挤额度）→ 精华/优质/普通分级 → 每吧最多 7 条、合计 20 条，逐条补详情正文。
   - `fund_guba`：`src/crawler/tiantian_crawler.py` 抓 10 只热门基金的基金吧
     （`161725` 白酒、`512880` 证券、`512480` 芯片等，见 `_default_fetchers.HOT_FUNDS`），
     地址必须是 `list,of<基金代码>.html`（of 前缀，2026-10-13 修复：裸代码会抓成同名股票吧、
     ETF 裸码直接 0 条）；新版吧页列表是服务端渲染 `div.articleh` 行（每页约 80 条），
     **列表阶段先按当天过滤**，再质量分级，合计最多 20 条。
4. **正文与权威时间**（2026-10-13 重写）：基金吧详情取
   `var post_article = {"post": {...}}` JSON（`post_content` 是正文、`post_publish_time` 是
   真实发帖时间；实测 `.gbbody` 容器是页头导航、列表行 `.l5` 时间往往是"最后回复时间"，
   两者都不可信）。列表显示今天、详情 JSON 说是昨天的"顶帖旧帖"，在核实后丢弃并用后续候选补位。
5. **逐条门禁**（`_process_article`）：去重（`crawler_article_records.article_id`）→
   仅当天（北京时间）→ 质量规则（标题/内容长度、垃圾关键词"荐股/牛股/内幕"等，
   `src/crawler/filters/`）→ 边界内容由轻量 AI（`quick_judge_viewpoint`）裁决，拿不准放行。
6. **产出**：通过的写入 `viewpoints` 表（`title/content/source/weight/expiration` 等）；
   任务回执 `result_summary.sources.<源>` 记 `fetched/adopted/duplicates/skipped/failed`
   与逐原因 `skipped_reasons`，前端轮询 `GET /api/viewpoints/tasks/latest` 展示。
   之后由「观点汇总」和「批量分析」消费（见帖子录入与LLM分析、投资建议两个总览）。

## 入口文件清单

- `src/crawler/sina_blog_crawler.py` / `stock_guba_crawler.py` / `tiantian_crawler.py`（三个源）
- `src/crawler/filters/`（质量与垃圾内容规则）
- `src/services/viewpoint_workflow_service.py`（抓取任务编排 + 逐条门禁）
- `src/api/routes/viewpoints.py`（`POST /fetch`、任务状态、重试）
- `web/viewpoint-manager.js`（抓取按钮与数据源多选）

## 对外接口 / 被谁调用

- HTTP：`POST /api/viewpoints/fetch`、`GET /api/viewpoints/tasks/latest`、`POST /api/viewpoints/tasks/{id}/retry`。
- 被调度器调用：`src/tasks/scheduler.py` 与 Render Cron（`scripts/run_scheduled_tasks.py daily`）
  按 `CRAWLER_ENABLED` 决定是否自动跑（本地默认手动触发即可）。
- 下游：`ViewpointService` 批量分析、`AdviceService`（投资建议读当天观点）、市场观点汇总。

## 依赖的上游模块

- `src/core/config.py`（`CRAWLER_TIMEOUT` / `CRAWLER_REQUEST_DELAY=2.0s` / `MAX_POSTS_PER_FUND`）。
- `src/analyzer/viewpoint_analyzer.py`（边界内容的轻量 AI 裁决）。
- 外部站点：finance.sina.com.cn、weibo.com（新浪博文正文）、guba.eastmoney.com（股吧/基金吧）。

## 关键数据结构

- 帖子字典：`title/content/author/publish_time/url/source/article_id`（股吧另有
  `read_count/reply_count/quality_level/is_essence`）。
- `viewpoints` 表行：source ∈ `sina_blog/stock_guba/fund_guba`，author 社区帖统一"网友"。
- 任务回执：`result_summary = {sources: {源: {fetched, adopted, duplicates, skipped, failed, skipped_reasons}}, ...}`。

## 已知坑与约束

- **"抓不到"通常是抓错了不是源死了**（2026-10-13 的教训）：基金吧地址少 `of` 前缀会撞同名股票吧；
  新版吧页没有 `var article_list=` JSON；正文容器取错会拿到整页导航。三条判据在
  `tests/unit/test_crawler/test_guba_today_dom.py`。
- **列表行时间不可信**：`.l5` 是"最后回复时间"，顶帖会把旧帖显示成今天；以详情 JSON 的
  `post_publish_time` 为权威（基金吧已实现，股吧列表 JSON 自带完整发帖时间）。
- **东财有反爬**：短时间高频（浏览器调试+脚本连打几十发）会吃 2826 字节的验证页
  （HTTP 200 但没内容）；爬虫遇到会打印"疑似触发东财反爬验证"并返回空，不硬重试。
  生产默认节流 2 秒/请求、手动低频触发是安全的。
- **时间判断一律北京时间**（`_BEIJING_TZ`）：Render 容器是 UTC，用墙钟日会在北京凌晨整源误杀。
- 新浪博文正文走微博 `ttarticle` API（`code=100000` 才算成功），列表页只有标题。
- 当天样本不足 10 条时任务回执带预警（不放松"仅当天"规则去补量）。
